# Domain docs

This repo uses a single domain context shared by the public site and museum dashboard.

## Before exploring

- Read `CONTEXT.md` at the repo root for domain terms.
- Read the ADRs in `docs/adr/` that cover the area you are working in.

If either path is absent, proceed with the available context. The domain-modeling skill creates these docs as terms and decisions are settled.

## Use the glossary

Use the glossary's terms in issue titles, proposals, hypotheses, and test names. If a concept has no glossary entry, check how the project names it and raise genuine vocabulary gaps during domain modeling.

## Flag ADR conflicts

When proposing work that conflicts with an ADR, identify the decision and explain why it may need to be revisited.
